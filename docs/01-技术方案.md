# 技术方案：把 QGIS 桌面版本身编译到浏览器

> English: [01-approach.md](en/01-approach.md)

> 不是用 Web 技术“模仿”一个 QGIS，而是把 QGIS 的 C++/Qt 源码（core + analysis + gui + app）用 Emscripten 编译成 WebAssembly，Qt 的窗口系统由 Qt for WebAssembly 平台插件接管，QGIS 自己的 QMainWindow、图层树、地图画布、属性表、符号化对话框……原封不动地画在一个 `<canvas>` 上。

## 1. 为什么可行

| 事实 | 依据 |
|---|---|
| QGIS core 已经能用 Emscripten 编译 | 上游项目 [qgis-js](https://github.com/qgis/qgis-js) 以 `WITH_GUI=OFF WITH_DESKTOP=OFF` 编译 QGIS master（4.2.3，commit `b041a189`），**不需要给 QGIS 打任何补丁**；其 vcpkg 工具链同时交付了 wasm 版 Qt 6.11.1、GDAL 3.12、PROJ 9.8、GEOS 3.14、sqlite、protobuf、libzip、exiv2 等 |
| Qt Widgets 在浏览器里是一等公民 | Qt for WebAssembly（`qwasm` 平台插件）用软件光栅 + WebGL 把 QWidget 绘制到 canvas，键鼠/剪贴板/拖放/多窗口都有实现；线程通过 SharedArrayBuffer（COOP/COEP）支持，`QThread`/`QtConcurrent`/`QgsMapRendererParallelJob` 可以直接工作 |
| QGIS 的构建系统本来就为“少功能”做了开关 | `WITH_QTPRINTER`（iOS 没有 QPrinter）、`WITH_QTWEBENGINE`、`WITH_AUTH`、`WITH_3D`、`WITH_BINDINGS`、`WITH_INTERNAL_QWT`、`WITH_CRASH_HANDLER`… 上游 CMake 里已经有 `EMSCRIPTEN` 分支（`FindWrapRt.cmake`、`src/core/CMakeLists.txt`、`qgsfileutils.cpp`、`qgsuserprofile.cpp`） |
| 嵌套事件循环（`QDialog::exec()`）有解 | Emscripten 的 JSPI（JavaScript Promise Integration，Chrome 137+ 默认开启）或 Asyncify 可以让主线程在 `exec()` 里“挂起”再恢复；Qt 的 wasm 事件分发器已经为此导出 `qt_asyncify_suspend_js / qt_asyncify_resume_js` |

## 2. 构建流水线

```
emsdk 6.0.10 ──┐
vcpkg 2026.07  ├─ triplet wasm32-emscripten-qt-threads (-pthread -fwasm-exceptions, release-only)
               │   ├─ qtbase[widgets,opengl,gles3,network,sql-sqlite,...]  (+ x64 host 工具: moc/uic/rcc/lrelease)
               │   ├─ qtdeclarative qtsvg qtmultimedia[widgets] qttools(UiTools) qt5compat qtkeychain
               │   ├─ gdal proj geos sqlite3 libspatialindex expat libzip protobuf zstd exiv2 freetype
               │   └─ qscintilla  ← 本仓库的 CMake 版 overlay port（上游只有 qmake 工程，且 QsciPrinter 需要 QPrinter）
               ▼
external/QGIS (git submodule, 上游 commit) + patches/qgis-wasm.patch
   cmake -DWITH_GUI=ON -DWITH_DESKTOP=ON -DWITH_ANALYSIS=ON -DFORCE_STATIC_LIBS=ON
         -DWITH_QTPRINTER=OFF -DWITH_AUTH=OFF -DWITH_QTWEBENGINE=OFF -DWITH_BINDINGS=OFF -DWITH_3D=OFF ...
   → libqgis_core.a libqgis_analysis.a libqgis_gui.a libqgis_app.a libqgis_native.a provider_*_a
   → qgis.js + qgis.wasm + qgis.data (+ qgis.html / qtloader.js)   ← src/app/main.cpp，QGIS 自己的入口
```

### 对 QGIS 源码的改动

全部在 `patches/qgis-wasm.patch`（`scripts/export-patches.sh` 重新生成）。按性质分四组。

**构建系统**

- **`src/app/CMakeLists.txt`**：`EMSCRIPTEN` 下 `qgis` 可执行目标改用 `qt_add_executable(MANUAL_FINALIZATION)`（并改成 keyword 形式的 `target_link_libraries`），不链接 `qt-unix-signals`；文末 `include(cmake/QgisWasmApp.cmake)`。
- **`cmake/QgisWasmApp.cmake`（新增）**：wasm 可执行目标的终结配置。
  - Emscripten 运行时：可增长的 4 GB 堆、预加载的 8–16 个 Worker 线程池、mimalloc、`FORCE_FILESYSTEM`、IDBFS。
  - `--preload-file` 把 `resources/`（srs.db、qgis.db、symbology-style.xml、主题、函数帮助、示例数据、全局设置）、`images/svg`、字体、demo 工程、PROJ 的 `proj.db` 打进虚拟文件系统。
  - JSPI / Asyncify 开关、`--profiling-funcs`。
  - `qt_finalize_executable`、`qt_import_qml_plugins`，并显式链接欢迎页的静态 QML 插件 `qgis_appplugin`。
  - 链接 `QGIS_WASM_STATIC_PLUGINS` 列出的静态 C++ 插件。
  - 导出 `qgis_wasm_open` / `qgis_wasm_call` / `qgis_wasm_ready`；把 `web/shell/` 整个目录拷到输出目录。
- **`src/CMakeLists.txt`**：wasm 下先构建 `src/plugins`（静态库）再构建 `src/app`，以便可执行文件链接它们。
- **`src/native/CMakeLists.txt`**：Emscripten 不是 Linux 桌面，不找 QtDBus，不编译 `qgslinuxnative.cpp`。
- **`src/gui/CMakeLists.txt`**：Qt 没有 SSL 时（wasm 恒成立）剔除证书/身份/SSL 配置这 12 个 widget；上游 core 本来就用 `QT_NO_SSL` 守卫对应 API。
- **`src/core/CMakeLists.txt`**：`WITH_AUTH=OFF` 时仍编译 gui 需要的 `qgsauthconfig.cpp`、`qgsauthmethodmetadata.cpp`（纯数据类）；顶层 `qgis_desktop` 辅助目标只在有 Python 绑定时依赖 Python 目标。
- 删除 QGIS 自带的 `FindGDAL / FindGEOS / FindEXIV2 / FindExpat / FindIconv / FindQtKeychain.cmake`，改用 vcpkg 导出的 CMake config（与 qgis-js 相同做法）。

**源码守卫**

全部用 `__EMSCRIPTEN__` / `QT_NO_SSL` / `QT_CONFIG(...)` / `HAVE_STATIC_PROVIDERS` 守卫，其它平台行为不变。

- **`src/app/main.cpp` + `src/app/qgswasmapp.{h,cpp}`**：浏览器下的全部差异收在 `QgsWasmApp` 的 5 个钩子里（`beforeApplication` / `applyDeploymentDefaults` / `beforeMainWindow` / `showMainWindow` / `afterInitialization`，在它们里面做：跳过 `DISPLAY` 检查、`Qt::AA_DontUseNativeDialogs`、随包字体目录、`setMaxThreads(8)`、浏览器友好的默认设置、应用 preset、全页面窗口与跟随页面尺寸、挂接控制面）。`main.cpp` 本身只剩一行行的 `QgsWasmApp::xxx()` 调用（约 30 行），升级 QGIS 时几乎不冲突；JS 入口 `qgis_wasm_open/ready/call` 也在 `qgswasmapp.cpp`。
- **SSL 守卫**：`qgsautheditorwidgets.cpp`、devtools 网络日志（`QSslError`）、`qgisapp.h/.cpp`、`qgsappsslerrorhandler.*`、`qgsabout.cpp`、`qgsauthconfig.cpp`（PKI 部分还需要 QCA）→ `#ifndef QT_NO_SSL` / `HAVE_AUTH`；`qgsauthmanager.cpp` 补两个无 auth 时的 stub。
- **`QT_CONFIG(process|networkproxy|timezone)`**：`qgscodeeditorwidget.cpp`（外部编辑器）、`qgscrashhandler.cpp`、`qgsoptions.cpp`（`QProcessEnvironment`）、`qgshelp.cpp` / `qgisapp.*`（代理认证）、`qgsdatetimeedit.cpp`、`qgsgpsoptions.cpp`（时区列表）。
- **`qgsnetworkaccessmanager.cpp`**：Emscripten 下不设置 `User-Agent` 请求头（浏览器禁止）。
- **静态链接带来的重复定义**：`qgsalgorithmb3dmtogltf.cpp` 不再重复编译 tinygltf 实现；`qgsgeometrysnapper.cpp` / `qgspointcloudlayerprofilegenerator.cpp` 的 `_GEOSQueryCallback` 改 `static`；`qgsappauthrequesthandler.cpp` 补 `<QThread>`。
- **`src/core/qgswasmtrace.h`（新增）** + 若干 `QGIS_WASM_TRACE(...)`：`QGIS_WASM_TRACE` 环境变量存在时，把渲染作业、画布刷新、工程读取、欢迎页、字体安装等关键路径输出到浏览器控制台（页面加 `?trace=1`）。

**浏览器部署能力**（都是新增文件，只在 `__EMSCRIPTEN__` 下编译；详见 [04-云存储-Preset-Agent.md](04-云存储-Preset-Agent.md) 与 [03-插件与迁移指南.md](03-插件与迁移指南.md)）

- **`src/app/qgswasmbridge.{h,cpp}`**：控制面。约 50 个带 JSON schema 的"工具"（工程、图层、要素、样式、画布、表达式、Processing、设置、XYZ 底图、虚拟文件系统、UI 动作、C++ 插件、助手），一份注册表同时服务页面 JS（`qgis_wasm_call()` 排队进 Qt 事件循环，`Module.qgisBridgeResolve/qgisBridgeEvent` 回传）、MCP 服务器和内置助手；工程/图层/画布/选择事件推送到页面。远程文件通过同步 XMLHttpRequest（EM_JS）下载到虚拟文件系统——主线程上的阻塞式 Qt 网络请求会卡死，见 [02-运行时与调试.md](02-运行时与调试.md)。
- **`src/app/qgswasmpreset.{h,cpp}`**：读取页面写入的 preset JSON（`QGIS_WASM_PRESET`），在主窗口创建前把设置（首次 / 强制）、XYZ 底图连接（`QgsXyzConnectionSettings`）、Browser 收藏夹（`QgsFavoritesItem`）、要启用的 C++ 插件写进用户配置文件。
- **`src/app/qgswasmstaticplugins.{h,cpp}`** + `src/plugins/qgisplugin.h` 的 `QGIS_PLUGIN_SYMBOL()` + `QgsPluginRegistry` / `QgsPluginManager` 的 `__EMSCRIPTEN__` 分支 + `src/plugins/*/CMakeLists.txt`：C++ 插件编成静态库链接进可执行文件，入口符号加前缀后登记在一张表里，插件管理器 / 会话恢复 / 加载卸载都查这张表；上游 Topology Checker 与 Geometry Checker 已编入。
- **`src/app/qgswasmbridge.cpp` 的 `qgis_version`**：返回 `bridgeApi`（工具契约的大版本），Web Agent 启动时比对。
- **（已移出 QGIS）Agent**：原来的 Assistant 停靠面板（Responses API + MCP 客户端，C++）已删除；agent 现在是页面上的独立模块 `web/agent/`，只通过 `QgsWasmBridge` 的工具契约操控 QGIS（docs/05）。QGIS 侧为此不含任何 agent 代码。

**依赖侧（vcpkg overlay ports）**

- `qscintilla`：CMake 构建（上游只有 qmake 工程，且 `QsciPrinter` 需要 `QPrinter`），并补 wasm32 上 `RunStyles<ptrdiff_t,…>` 的显式实例化。
- `libb2`：CMake 构建，不需要 autotools。
- `json-c`、`libspatialindex`（来自 qgis-js）。
- 清单里为 gui/app 增加 `qtdeclarative`、`qtmultimedia[widgets]`、`qttools`（UiTools）、`gsl`；宿主 Qt 需要 `thread` 特性。

### 明确放弃的功能（“可以兼容少功能”）

| 功能 | 原因 |
|---|---|
| Python / PyQGIS / Python 插件 / Processing 的 Python 算法 | 浏览器里没有 CPython+SIP 绑定到同一份 wasm 内存的可行方案；C++ 的 `native:*` 处理算法仍在 |
| HTTPS 证书管理、认证配置数据库 (`WITH_AUTH`) | Qt for WebAssembly 没有 QSsl*；HTTP(S) 请求本身由浏览器 fetch 完成，仍然可用 |
| 打印 / 打印预览 | 没有 QPrinter；布局（Layout）编辑器与导出图片仍可编译 |
| 3D 视图、QtWebEngine 文档面板、串口 GPS、QtPositioning | 对应 Qt 模块在 wasm 上不存在 |
| PostgreSQL / Spatialite / GRASS / PDAL 等需要 socket 或巨大依赖的 provider | 浏览器没有原始 socket；只保留 GDAL/OGR、delimitedtext、WMS/WCS、ArcGIS REST、XYZ 等 |
| 运行时加载 C++ 插件（`.so`）、崩溃处理器、DBus 桌面集成 | 静态链接 / 无进程模型；C++ 插件改为编译期静态编入（docs/03） |

## 3. 运行时

- **文件系统**：Emscripten MEMFS 为根；`/qgis/share/qgis/...` 为预加载的 QGIS 数据目录（`QGIS_PREFIX_PATH=/qgis`）；`/proj` 为 PROJ 数据；`/qgis/share/demo` 示例工程；用户目录 `/home/web_user` 挂 IDBFS（刷新后设置、工程文件仍在）；`/cloud/<name>` 是 `web/shell/cloudfs.js` 挂载的对象存储（S3 兼容 / HTTP 目录，docs/04）；`?open=URL` 把远程文件 `fetch` 到 `/home/web_user/downloads/` 后交给 `QgisApp::openFile()`。
- **网络**：QNetworkAccessManager → 浏览器 fetch（受 CORS 约束；WMS/XYZ 等公开服务通常允许）。
- **线程**：Qt wasm 线程版，启动时预加载 8–16 个 Worker，QGIS 渲染线程上限 8，并行渲染作业直接可用。
- **嵌套事件循环**：`-sJSPI`（默认，Chrome 137+）或 `-sASYNCIFY`；JS 调入 C++ 必须排队进 Qt 事件循环（见 docs/02 §2.1）。
- **规模**：`qgis.wasm` 133 MB（Release，含函数名）、`qgis.data` 19 MB（13 MB 的 `world_map.gpkg` 改为首次读取时下载，docs/06 §5）；传输用预压缩的旁路文件（brotli 30.7 + 2.9 MB，`scripts/compress-bundle.mjs`，docs/06 §5）；Chrome 149 下主窗口约 2.4 s 出现（32 核 + tmpfs 的机器上曾量到 8 s，差异主要是浏览器写缓存档案的磁盘 I/O，见 docs/06 §7），demo 工程约 10 s 渲染完成。

详细的运行时发现与调试手段见 [02-运行时与调试.md](02-运行时与调试.md)。
