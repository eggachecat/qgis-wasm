# Technical approach: compiling QGIS Desktop itself into the browser

> Chinese original: [01-技术方案.md](../01-技术方案.md)

> Not a QGIS "imitation" built with web technologies, but QGIS' own C++/Qt source (core + analysis + gui + app) compiled to WebAssembly with Emscripten; Qt's window system is taken over by the Qt for WebAssembly platform plugin, and QGIS' own QMainWindow, layer tree, map canvas, attribute table, symbology dialogs… are drawn unchanged on a `<canvas>`.

## 1. Why it works

| Fact | Basis |
|---|---|
| QGIS core already compiles with Emscripten | The upstream project [qgis-js](https://github.com/qgis/qgis-js) compiles QGIS master (4.2.3, commit `b041a189`) with `WITH_GUI=OFF WITH_DESKTOP=OFF`, **without any patch to QGIS**; its vcpkg toolchain also ships wasm builds of Qt 6.11.1, GDAL 3.12, PROJ 9.8, GEOS 3.14, sqlite, protobuf, libzip, exiv2 and others |
| Qt Widgets is a first-class citizen in the browser | Qt for WebAssembly (the `qwasm` platform plugin) draws QWidgets onto a canvas with software rasterization + WebGL; keyboard/mouse, clipboard, drag and drop and multiple windows are all implemented; threads are supported through SharedArrayBuffer (COOP/COEP), and `QThread`/`QtConcurrent`/`QgsMapRendererParallelJob` work directly |
| QGIS' build system already has switches for "fewer features" | `WITH_QTPRINTER` (iOS has no QPrinter), `WITH_QTWEBENGINE`, `WITH_AUTH`, `WITH_3D`, `WITH_BINDINGS`, `WITH_INTERNAL_QWT`, `WITH_CRASH_HANDLER`… upstream CMake already has `EMSCRIPTEN` branches (`FindWrapRt.cmake`, `src/core/CMakeLists.txt`, `qgsfileutils.cpp`, `qgsuserprofile.cpp`) |
| Nested event loops (`QDialog::exec()`) have a solution | Emscripten's JSPI (JavaScript Promise Integration, on by default in Chrome 137+) or Asyncify can suspend the main thread inside `exec()` and resume it later; Qt's wasm event dispatcher already exports `qt_asyncify_suspend_js / qt_asyncify_resume_js` for this |

## 2. Build pipeline

```
emsdk 6.0.10 ──┐
vcpkg 2026.07  ├─ triplet wasm32-emscripten-qt-threads (-pthread -fwasm-exceptions, release-only)
               │   ├─ qtbase[widgets,opengl,gles3,network,sql-sqlite,...]  (+ x64 host tools: moc/uic/rcc/lrelease)
               │   ├─ qtdeclarative qtsvg qtmultimedia[widgets] qttools(UiTools) qt5compat qtkeychain
               │   ├─ gdal proj geos sqlite3 libspatialindex expat libzip protobuf zstd exiv2 freetype
               │   └─ qscintilla  ← this repository's CMake overlay port (upstream has only a qmake project, and QsciPrinter needs QPrinter)
               ▼
external/QGIS (git submodule, upstream commit) + patches/qgis-wasm.patch
   cmake -DWITH_GUI=ON -DWITH_DESKTOP=ON -DWITH_ANALYSIS=ON -DFORCE_STATIC_LIBS=ON
         -DWITH_QTPRINTER=OFF -DWITH_AUTH=OFF -DWITH_QTWEBENGINE=OFF -DWITH_BINDINGS=OFF -DWITH_3D=OFF ...
   → libqgis_core.a libqgis_analysis.a libqgis_gui.a libqgis_app.a libqgis_native.a provider_*_a
   → qgis.js + qgis.wasm + qgis.data (+ qgis.html / qtloader.js)   ← src/app/main.cpp, QGIS' own entry point
```

### Changes to the QGIS source

All in `patches/qgis-wasm.patch` (regenerated by `scripts/export-patches.sh`). Four groups by nature.

**Build system**

- **`src/app/CMakeLists.txt`**: under `EMSCRIPTEN` the `qgis` executable target switches to `qt_add_executable(MANUAL_FINALIZATION)` (and to the keyword form of `target_link_libraries`), does not link `qt-unix-signals`; at the end, `include(cmake/QgisWasmApp.cmake)`.
- **`cmake/QgisWasmApp.cmake` (new)**: finalization configuration for the wasm executable target.
  - Emscripten runtime: a growable 4 GB heap, a preloaded pool of 8–16 Worker threads, mimalloc, `FORCE_FILESYSTEM`, IDBFS.
  - `--preload-file` packs `resources/` (srs.db, qgis.db, symbology-style.xml, themes, function help, sample data, global settings), `images/svg`, fonts, the demo project and PROJ's `proj.db` into the virtual filesystem.
  - JSPI / Asyncify switches, `--profiling-funcs`.
  - `qt_finalize_executable`, `qt_import_qml_plugins`, plus an explicit link of the welcome page's static QML plugin `qgis_appplugin`.
  - Links the static C++ plugins listed in `QGIS_WASM_STATIC_PLUGINS`.
  - Exports `qgis_wasm_open` / `qgis_wasm_call` / `qgis_wasm_ready`; copies the whole `web/shell/` directory into the output directory.
- **`src/CMakeLists.txt`**: under wasm, build `src/plugins` (static libraries) before `src/app`, so that the executable can link them.
- **`src/native/CMakeLists.txt`**: Emscripten is not Linux desktop — do not look for QtDBus, do not compile `qgslinuxnative.cpp`.
- **`src/gui/CMakeLists.txt`**: when Qt has no SSL (always true on wasm), drop the 12 certificate/identity/SSL-configuration widgets; upstream core already guards the corresponding APIs with `QT_NO_SSL`.
- **`src/core/CMakeLists.txt`**: with `WITH_AUTH=OFF` still compile `qgsauthconfig.cpp` and `qgsauthmethodmetadata.cpp` (pure data classes) that gui needs; the top-level `qgis_desktop` helper target depends on the Python target only when Python bindings are enabled.
- Remove QGIS' bundled `FindGDAL / FindGEOS / FindEXIV2 / FindExpat / FindIconv / FindQtKeychain.cmake` and use the CMake config exported by vcpkg instead (the same approach as qgis-js).

**Source guards**

All guarded with `__EMSCRIPTEN__` / `QT_NO_SSL` / `QT_CONFIG(...)` / `HAVE_STATIC_PROVIDERS`; behaviour on other platforms is unchanged.

- **`src/app/main.cpp` + `src/app/qgswasmapp.{h,cpp}`**: all browser differences are confined to 5 hooks of `QgsWasmApp` (`beforeApplication` / `applyDeploymentDefaults` / `beforeMainWindow` / `showMainWindow` / `afterInitialization`, which do: skip the `DISPLAY` check, `Qt::AA_DontUseNativeDialogs`, bundled font directory, `setMaxThreads(8)`, browser-friendly default settings, apply presets, a full-page window that follows the page size, attach the control surface). `main.cpp` itself is left with nothing but line-by-line `QgsWasmApp::xxx()` calls (about 30 lines), so it almost never conflicts when upgrading QGIS; the JS entry points `qgis_wasm_open/ready/call` also live in `qgswasmapp.cpp`.
- **SSL guards**: `qgsautheditorwidgets.cpp`, the devtools network log (`QSslError`), `qgisapp.h/.cpp`, `qgsappsslerrorhandler.*`, `qgsabout.cpp`, `qgsauthconfig.cpp` (the PKI part also needs QCA) → `#ifndef QT_NO_SSL` / `HAVE_AUTH`; `qgsauthmanager.cpp` gains two stubs for the no-auth case.
- **`QT_CONFIG(process|networkproxy|timezone)`**: `qgscodeeditorwidget.cpp` (external editor), `qgscrashhandler.cpp`, `qgsoptions.cpp` (`QProcessEnvironment`), `qgshelp.cpp` / `qgisapp.*` (proxy authentication), `qgsdatetimeedit.cpp`, `qgsgpsoptions.cpp` (time zone list).
- **`qgsnetworkaccessmanager.cpp`**: under Emscripten the `User-Agent` request header is not set (browsers forbid it).
- **Duplicate definitions caused by static linking**: `qgsalgorithmb3dmtogltf.cpp` no longer compiles the tinygltf implementation twice; `_GEOSQueryCallback` in `qgsgeometrysnapper.cpp` / `qgspointcloudlayerprofilegenerator.cpp` becomes `static`; `qgsappauthrequesthandler.cpp` adds `<QThread>`.
- **`src/core/qgswasmtrace.h` (new)** + a number of `QGIS_WASM_TRACE(...)` calls: when the `QGIS_WASM_TRACE` environment variable is present, key paths such as render jobs, canvas refresh, project reading, the welcome page and font installation are printed to the browser console (add `?trace=1` to the page).

**Browser deployment capabilities** (all new files, compiled only under `__EMSCRIPTEN__`; see [04-cloud-presets-and-agent.md](04-cloud-presets-and-agent.md) and [03-plugins-and-migration.md](03-plugins-and-migration.md) for details)

- **`src/app/qgswasmbridge.{h,cpp}`**: the control surface. About 50 "tools" with JSON schemas (project, layers, features, styles, canvas, expressions, Processing, settings, XYZ basemaps, virtual filesystem, UI actions, C++ plugins, assistant); one registry serves page JS (`qgis_wasm_call()` queues into the Qt event loop, results come back through `Module.qgisBridgeResolve/qgisBridgeEvent`), the MCP server and the built-in assistant at the same time; project/layer/canvas/selection events are pushed to the page. Remote files are downloaded into the virtual filesystem with a synchronous XMLHttpRequest (EM_JS) — a blocking Qt network request on the main thread would deadlock, see [02-runtime-and-debugging.md](02-runtime-and-debugging.md).
- **`src/app/qgswasmpreset.{h,cpp}`**: reads the preset JSON written by the page (`QGIS_WASM_PRESET`) and, before the main window is created, writes settings (first run / forced), XYZ basemap connections (`QgsXyzConnectionSettings`), Browser favourites (`QgsFavoritesItem`) and the C++ plugins to enable into the user profile.
- **`src/app/qgswasmstaticplugins.{h,cpp}`** + `QGIS_PLUGIN_SYMBOL()` in `src/plugins/qgisplugin.h` + the `__EMSCRIPTEN__` branches of `QgsPluginRegistry` / `QgsPluginManager` + `src/plugins/*/CMakeLists.txt`: C++ plugins are built as static libraries linked into the executable, their entry symbols get a prefix and are registered in one table, and the plugin manager / session restore / load and unload all consult that table; upstream Topology Checker and Geometry Checker are already compiled in.
- **`qgis_version` in `src/app/qgswasmbridge.cpp`**: returns `bridgeApi` (the major version of the tool contract), which the Web Agent compares at startup.
- **(moved out of QGIS) Agent**: the former Assistant dock panel (Responses API + MCP client, in C++) has been deleted; the agent is now a separate module on the page, `web/agent/`, and drives QGIS only through the `QgsWasmBridge` tool contract ([docs/05](05-web-agent.md)). The QGIS side therefore contains no agent code.

**Dependency side (vcpkg overlay ports)**

- `qscintilla`: CMake build (upstream has only a qmake project, and `QsciPrinter` needs `QPrinter`), plus an explicit instantiation of `RunStyles<ptrdiff_t,…>` on wasm32.
- `libb2`: CMake build, no autotools needed.
- `json-c`, `libspatialindex` (from qgis-js).
- The manifest adds `qtdeclarative`, `qtmultimedia[widgets]`, `qttools` (UiTools) and `gsl` for gui/app; the host Qt needs the `thread` feature.

### Features explicitly given up ("compatible with fewer features" is acceptable)

| Feature | Reason |
|---|---|
| Python / PyQGIS / Python plugins / Python algorithms in Processing | there is no feasible way in the browser to bind CPython+SIP to the same wasm memory; the C++ `native:*` processing algorithms remain |
| HTTPS certificate management, authentication configuration database (`WITH_AUTH`) | Qt for WebAssembly has no QSsl*; HTTP(S) requests themselves are done by the browser fetch and still work |
| Printing / print preview | there is no QPrinter; the Layout editor and image export still compile |
| 3D views, QtWebEngine documentation panel, serial GPS, QtPositioning | the corresponding Qt modules do not exist on wasm |
| Providers such as PostgreSQL / Spatialite / GRASS / PDAL that need sockets or huge dependencies | the browser has no raw sockets; only GDAL/OGR, delimitedtext, WMS/WCS, ArcGIS REST, XYZ and similar are kept |
| Loading C++ plugins (`.so`) at runtime, crash handler, DBus desktop integration | static linking / no process model; C++ plugins are instead statically linked in at compile time ([docs/03](03-plugins-and-migration.md)) |

## 3. Runtime

- **Filesystem**: Emscripten MEMFS as root; `/qgis/share/qgis/...` is the preloaded QGIS data directory (`QGIS_PREFIX_PATH=/qgis`); `/proj` is the PROJ data; `/qgis/share/demo` is the sample project; the user directory `/home/web_user` mounts IDBFS (settings and project files survive a refresh); `/cloud/<name>` are the object stores mounted by `web/shell/cloudfs.js` (S3-compatible / HTTP directory, [docs/04](04-cloud-presets-and-agent.md)); `?open=URL` fetches the remote file into `/home/web_user/downloads/` and hands it to `QgisApp::openFile()`.
- **Network**: QNetworkAccessManager → browser fetch (subject to CORS; public services such as WMS/XYZ usually allow it).
- **Threads**: the Qt wasm thread build, 8–16 Workers preloaded at startup, QGIS render threads capped at 8, parallel render jobs work directly.
- **Nested event loop**: `-sJSPI` (default, Chrome 137+) or `-sASYNCIFY`; calls from JS into C++ must be queued into the Qt event loop (see [docs/02](02-runtime-and-debugging.md) §2.1).
- **Scale**: `qgis.wasm` 133 MB (Release, with function names), `qgis.data` 19 MB (the 13 MB `world_map.gpkg` is downloaded on first read instead, [docs/06](06-architecture.md) §5); transport uses pre-compressed sidecar files (brotli 30.7 + 2.9 MB, `scripts/compress-bundle.mjs`, [docs/06](06-architecture.md) §5); in Chrome 149 the main window appears in ≈ 2.4 s (measured ≈ 8 s on a 32-core machine with a tmpfs browser profile — the difference is disk I/O while Chrome writes the profile, see [docs/06](06-architecture.md) §7) and the demo project finishes rendering in ≈ 10 s.

Detailed runtime findings and debugging methods: [02-runtime-and-debugging.md](02-runtime-and-debugging.md).
